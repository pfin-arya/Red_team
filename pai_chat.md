## 📘 API Documentation: `pai_chat`

### **Overview**
This API is the main entry point for the PAI@HR conversational assistant. It accepts a message from an employee, routes it to the appropriate AI agent (HR query, cab booking, letter generation, etc.), persists the conversation in MongoDB, and returns a structured response. It supports multi-turn conversations, file attachments, and intent-based agent dispatch.

---

### **Endpoint**
```
https://pfl-aiml-prod.azurewebsites.net/api/pai_chat?
```

---

### **Authentication**
- **Auth Level**: `Function`
- Requires a valid Azure Function key passed as a query parameter (`?code=<key>`) or in the `x-functions-key` header.

---

### **Request Headers**
| Header Name   | Type   | Required | Description                |
|---------------|--------|----------|----------------------------|
| Content-Type  | string | Yes      | Must be `application/json` |

---

### **Request Body**
```json
{
  "employee_email": "string",
  "message": "string",
  "channel": {
    "name": "string",
    "tenant_id": "string"
  },
  "attachments": [
    {
      "name": "string",
      "blob_container": "string",
      "blob_name": "string",
      "content_type": "string",
      "size_bytes": "integer",
      "source": "string"
    }
  ]
}
```

#### **Field Descriptions**
| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `employee_email` | string | Yes* | Employee's email address. Also accepted as `email` or `userEmail`. |
| `message` | string | Yes* | The user's chat message. Also accepted as `query` or `question`. If omitted but `attachments` is provided, a default message is auto-generated. |
| `channel` | object | No | Channel context (e.g. `{"name": "teams"}`). Defaults to `{"name": "teams"}`. Also accepted as `channel_name` string. |
| `attachments` | array | No | List of file attachment metadata objects referencing blobs in Azure Storage. |

> \* At least one of `employee_email`/`email`/`userEmail` and one of `message`/`query`/`question` must be present (or attachments must be provided to auto-generate the message).

#### **Attachment Object Fields**
| Field | Type | Description |
|-------|------|-------------|
| `name` | string | Display filename |
| `blob_container` | string | Azure Blob Storage container name |
| `blob_name` / `blob_path` | string | Path of the blob within the container |
| `content_type` | string | MIME type (e.g. `application/pdf`) |
| `size_bytes` | integer | File size in bytes |
| `source` | string | Source identifier for the attachment |

---

### **Response**
- **Content-Type**: `application/json`
- **Status Code**: `200 OK` on success

#### **Response Body**
```json
{
  "conversation_id": "string",
  "turn_id": "string",
  "task_id": "string | null",
  "active_agent": "string",
  "intent": "string",
  "confidence": "float",
  "message": "string",
  "file_paths": ["string"],
  "approval_requests": []
}
```

#### **Response Field Descriptions**
| Field | Type | Description |
|-------|------|-------------|
| `conversation_id` | string | Unique ID for the ongoing conversation (persisted in MongoDB) |
| `turn_id` | string | Unique ID for this specific turn |
| `task_id` | string \| null | ID of the active task, or `null` if no task was created |
| `active_agent` | string | The agent that handled this turn (e.g. `hr_query_agent`, `cab_booking_agent`) |
| `intent` | string | Classified intent of the user message |
| `confidence` | float | Confidence score (0.0–1.0) of the routing decision |
| `message` | string | The AI-generated reply to send back to the user |
| `file_paths` | array | List of blob/file URLs generated by the agent (e.g. generated letters) |
| `approval_requests` | array | Approval workflow objects if any action requires approval |

### **Supported Agents**

| Agent ID | Intent | Description |
|----------|--------|-------------|
| `hr_query_agent` | HR policy queries | Answers employee questions about HR policies, benefits, and procedures |
| `cab_booking_agent` | Cab booking | Books, modifies, or cancels cab requests |
| `letter_generation_agent` | Letter generation | Generates HR letters (visa, residence, BH plate, etc.) |
| `general_conversation_agent` | General / fallback | Handles greetings, out-of-scope queries, and general conversation |
| `fallback_agent` | Unknown intent | Fallback when no specific agent matches |

---

### **Conversation Close**
Sending any of the following messages will close the active conversation:

> `bye`, `goodbye`, `end chat`, `close conversation`, `close chat`, `end conversation`, `thanks bye`, `thank you bye`

The response `active_agent` will be `general_conversation_agent` with `intent: conversation_close`.

---

### **Function Logic**

1. **Request Parsing**: Extracts `employee_email`, `message`, `channel`, and `attachments` from the JSON body, supporting multiple field name aliases.
2. **Conversation Management**: Loads or creates a MongoDB conversation document for the employee+channel pair.
3. **Message Persistence**: Appends the incoming user message (with attachment metadata) to the conversation's `messages[]` array.
4. **Conversation Close Check**: If the message matches a close intent regex, the conversation is closed and an acknowledgement is returned immediately.
5. **Routing**: Calls the orchestrator `route()` to classify intent, select the appropriate agent, and produce a routing decision with extracted entities.
6. **Task Management**: Calls `apply_routing_decision()` to create or resume a task in MongoDB.
7. **Past DateTime Guard**: For `cab_booking_agent` and `letter_generation_agent`, validates that all date/time entities are in the future. If not, prompts the user to provide a future date before proceeding.
8. **Agent Dispatch**: Routes to the selected agent function with merged entities (including any previously collected fields from pending state).
9. **Pending State Management**: Stores follow-up questions and partially collected fields in `state.pending_user_inputs` in MongoDB for multi-turn data collection.
10. **Response Persistence**: Appends the assistant's reply to `messages[]` and updates conversation metrics.

### **Example Request**
```json
{
  "employee_email": "john.doe@company.com",
  "message": "I need a visa letter for my travel to Singapore from 01-08-2026 to 10-08-2026",
  "channel": {
    "name": "teams"
  }
}
```

### **Example Response**
```json
{
  "conversation_id": "conv_abc123",
  "turn_id": "turn_xyz456",
  "task_id": "task_def789",
  "active_agent": "letter_generation_agent",
  "intent": "letter_generation_visa",
  "confidence": 0.95,
  "message": "I'll generate your visa letter for Singapore travel from 01-Aug-2026 to 10-Aug-2026. Please confirm the date you plan to resume work.",
  "file_paths": [],
  "approval_requests": []
}
```

### **Example — Attachment Upload**
```json
{
  "employee_email": "john.doe@company.com",
  "channel": { "name": "teams" },
  "attachments": [
    {
      "name": "offer_letter.pdf",
      "blob_container": "pai-uploads",
      "blob_name": "uploads/john.doe/offer_letter.pdf",
      "content_type": "application/pdf",
      "size_bytes": 204800
    }
  ]
}
```
> When only attachments are provided with no `message`, the message is auto-set to: `"Uploaded file(s): offer_letter.pdf"`.
